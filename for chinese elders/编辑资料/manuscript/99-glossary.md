# 附录 A　AI 中英文词汇与生活比方

## 怎样使用这份词汇表

不需要一次背完。遇到陌生词时，先读“准确解释”，再用比方建立直觉，最后一定要读“比方的边界”。比方帮助理解，但不能代替真实原理。

每个工程概念最终都要回到用户的实际选择。可以先用下面这张表判断“我为什么需要知道这个词”：

| 您正在作出的决定 | 需要理解的词 | 理解后能避免什么 |
|---|---|---|
| 选择免费 App 还是付费服务 | App、API、模型路由、额度 | 把普通接口调用误认为独家模型 |
| 判断答案是否可靠 | 上下文、知识截止时间、幻觉、RAG | 把流畅回答或虚假引用当事实 |
| 选择大模型还是小模型 | LLM、SLM、本地运行、延迟 | 为简单任务多付费，或误信“本地”宣传 |
| 上传文件和家庭照片 | 服务器、云端、记忆、个人信息 | 在不知道保存位置时交出敏感资料 |
| 使用 AI 写作、作图或修照片 | 提示词、图片生成、局部重绘、增强 | 把模型补出的内容误认为真实细节 |
| 购买“专业训练”产品 | 系统提示词、知识库、RAG、微调 | 把几行隐藏指令当作昂贵专业训练 |
| 让 AI 帮忙编程 | 代码、依赖、运行环境、API 密钥、测试 | 运行危险命令或泄露能够产生费用的密钥 |
| 比较厂商宣传 | 基准测试、版本、速率限制、开放权重 | 把单项高分、“无限量”或“开源”理解过头 |

## 工程概念对用户的直接意义索引

下面不是另一套定义，而是回答同一个问题：**理解这个词以后，我的操作或判断应该发生什么变化？**

#### 基础模型概念

| 工程词 | 作为用户，这对您意味着什么 |
|---|---|
| 人工智能（AI） | 不接受“这是 AI”作为质量证明，继续询问具体模型、用途和责任主体。 |
| 算法 | 推荐和排序由目标与规则决定；系统反复给您看某类内容，不表示它判断该内容真实。 |
| 模型 | 同一 App 可以换模型，同一模型也能进入不同 App；选择产品不能只看界面名称。 |
| 机器学习 | 系统会继承训练数据中的错误和偏见，不能因为“自动学会”就免于核验。 |
| 生成式 AI | 它擅长创造新内容，因此尤其要区分生成结果、原始证据和历史事实。 |
| 训练 | 一次普通聊天通常不是重新训练基础模型；商家称“专门训练”时应提供数据和评估证据。 |
| 推理或运行 | 每次生成都会消耗计算资源；速度、费用和额度常发生在这个阶段。 |
| 参数 | 参数数量只是规模指标之一，不能直接换算成准确性、中文水平或专业资格。 |
| 数据集 | 训练材料的来源、授权和质量会影响模型；“数据很多”不等于“数据可靠”。 |
| 数据污染 | 错误、过期、重复或失衡资料可能影响模型；重要答案仍要追到原始来源。 |
| 数据投毒 | 这是带有操纵意图的训练阶段攻击，不应与普通资料错误混为一谈。 |
| 模型坍塌 | 大量递归吸收未经控制的模型生成内容可能损失少数细节，但合成数据并非一概有害。 |

#### 语言与信息处理

| 工程词 | 作为用户，这对您意味着什么 |
|---|---|
| Token | 长文件、长对话和长回答通常增加费用与额度消耗，计费不能只按“问了几次”理解。 |
| 大型语言模型（LLM） | 适合广泛解释和写作，但流畅语言不能代替事实来源和职业资格。 |
| 小型语言模型（SLM） | 简单、本机和快速任务可能不需要最贵模型，但要确认数据是否真的没有上传。 |
| 上下文 | 当前对话和文件会影响回答；换新对话或遗漏材料，结果可能明显变化。 |
| 上下文窗口 | “能上传很多页”不等于每一页都读准，长文件仍要追问原文位置与例外。 |
| 知识截止时间 | 涉及今天的价格、政策、人物和新闻时，要使用联网来源并检查日期。 |
| 幻觉 | 书名、引用、日期和人物经历都可能被编造；格式越完整，越不能放弃打开来源。 |

#### 图片、声音和多模态

| 工程词 | 作为用户，这对您意味着什么 |
|---|---|
| 多模态模型 | “支持图片”可能只代表能看，未必能生成、编辑或可靠读图；要测试具体任务。 |
| OCR | 扫描文字需要逐字对照原图，尤其是姓名、药名、数字和手写字。 |
| 语音识别 | 会议记录和口述稿要复核专有名词；声音转成整齐文字不表示完全听准。 |
| 语音合成（TTS） | 可用于朗读和学习，但真人声音模仿涉及授权、冒充和诈骗风险。 |
| 图片生成 | 适合创意内容，不应把生成画面当作新闻、证据或真实历史照片。 |
| 局部重绘 | 要明确框选区域和不变量；模型填补的是推测，不一定恢复原始细节。 |
| 放大与增强 | “更清楚”可能包含新生成纹理，老照片必须保留原始扫描作对照。 |

#### 产品、费用与数据流

| 工程词 | 作为用户，这对您意味着什么 |
|---|---|
| App | 需要核对开发者、隐私政策、付款主体和模型来源，而不只看图标与功能按钮。 |
| 用户界面（UI） | 界面漂亮或按钮很多不等于后台模型多、能力强或数据安全。 |
| 图形用户界面（GUI） | 网页、手机按钮只是操作方式，不是模型能力或研发归属的证明。 |
| 终端与命令行界面（CLI） | 模型不必做成 App 才能使用；但终端工具的云端费用、文件权限和命令风险仍要核对。 |
| API | 第三方可以低成本调用外部模型；高价产品应解释界面之外的真实附加价值。 |
| API 密钥 | 它能产生费用和权限，绝不能交给销售人员、陌生客服或放进公开网页。 |
| 服务器 | 输入内容可能离开手机，必须了解处理主体、保存位置和删除方式。 |
| 云端与本地运行 | “本地”不能只听宣传，要确认断网能否工作、网络权限和隐私条款。 |
| 模型路由 | 免费用户和会员可能使用不同模型；产品应说明何时切换以及能否查看实际版本。 |

#### 提示词、资料和定制

| 工程词 | 作为用户，这对您意味着什么 |
|---|---|
| 提示词 | 清楚交代任务、材料、输出和限制，能减少猜测，但不能保证事实正确。 |
| 系统提示词 | “专家角色”和商品倾向可能由后台隐藏说明产生，并不证明专业训练。 |
| 提示词工程 | 不必购买神秘口诀；价值在于分阶段说明和验收自己的真实任务。 |
| 知识库 | 要询问资料由谁选择、多久更新、是否只有销售方材料和能否查看原文。 |
| 嵌入模型 | 搜索结果“意思相近”不表示来源权威，仍需打开原文核对。 |
| RAG | 有引用比没有好，但必须检查引用是否真正支持结论以及资料库是否片面。 |
| 微调 | “经过微调”不等于最新或专业；要看它具体改善了哪项可测试任务。 |
| 记忆 | 便利来自长期保存资料；应定期查看、删除并避免保存疾病、证件和财务细节。 |
| 工具调用 | 搜索和读取与发送、付款、删除的风险不同，重要动作必须执行前确认。 |
| 智能体 | 连续自动化会连续放大错误；需要最小权限、日志、停止按钮和人工审批。 |

#### 比较产品和版本

| 工程词 | 作为用户，这对您意味着什么 |
|---|---|
| 基准测试 | 只把分数用于对应任务，不能把厂商单项高分当作日常全面质量。 |
| 延迟 | 更快不一定更准，更慢不一定思考更深；要按任务决定等待是否值得。 |
| 速率限制和额度 | “不限量”仍可能限速、限 Token 或受公平使用规则；付款前查看细则。 |
| 模型版本 | App 没升级，后台也可能换模型；重要任务记录产品、模型和日期。 |
| 开放权重与闭源服务 | 开放权重不等于全部开源或无需维护，闭源也不自动更安全；看许可证和实际部署。 |

#### AI 辅助编程

| 工程词 | 作为用户，这对您意味着什么 |
|---|---|
| 程序代码 | 先要求解释会读取、创建、修改和删除什么，再决定是否运行。 |
| 依赖 | 陌生依赖会增加安装和安全风险；简单工具优先使用较少依赖。 |
| 运行环境 | 提问时说明设备、系统和版本，不能把不同系统的命令直接互用。 |
| 错误信息 | 分享前删除用户名、文件路径、密钥和账号，但保留错误类型与发生步骤。 |
| 测试 | 先写可观察的验收标准；每次修改后同时复测新旧功能。 |

#### 隐私与信息判断

| 工程词 | 作为用户，这对您意味着什么 |
|---|---|
| 个人信息 | 单项普通信息也会与其他信息组合识别个人，上传前先做最小化和匿名化。 |
| 敏感个人信息 | 病历、证件、生物识别、金融和行踪资料不应随便交给不透明 AI。 |
| 个性化推荐 | 您和朋友反复看到同类内容可能是推荐结果，不是多个独立证据。 |
| 事实、推断与意见 | 要求 AI 分栏输出，并对事实找来源、对推断找反例、对意见保留个人判断。 |

## 一、最基础的几个词

### 人工智能（Artificial Intelligence, AI）

**准确解释：** 人工智能是一个很大的技术领域，研究和制造能够完成识别、预测、规划、生成内容等任务的计算系统。垃圾邮件过滤、地图路线、视频推荐和生成文章都可能使用 AI，但它们的工作方法并不相同。

**【这是一个比方】** “人工智能”像“交通工具”这个总称。自行车、火车、救护车和货轮都属于交通工具，却解决不同问题。

**【比方的边界】** AI 不是一组真的车辆，也不存在一个统管所有 AI 的发动机。“AI”只是大类名称，判断能力时必须继续问具体是什么模型和产品。

### 算法（algorithm）

**准确解释：** 算法是一套解决问题或处理数据的明确步骤。排序联系人、推荐视频、寻找路线都可以使用算法。算法不一定会学习；许多算法由人直接写出规则。

**【这是一个比方】** 算法有点像菜谱：规定先做什么、后做什么，以及遇到某种情况怎样处理。

**【比方的边界】** 菜谱由厨师理解并灵活执行，计算机算法则需要能够被机器精确执行。现代机器学习模型的内部计算也远比普通菜谱复杂。

### 模型（model）

**准确解释：** 模型是从数据中学习到一组数学关系、能够根据新输入产生预测或内容的计算系统。语言模型生成文字，图片模型生成或修改图像，分类模型判断内容属于哪一类。

**【这是一个比方】** 模型像一个经过大量练习形成工作习惯的助手：见过许多例子后，面对新材料会按学到的规律处理。

**【比方的边界】** 模型不是有生活经历、责任感和自我意识的人。所谓“学习”是调整大量数字参数，不是人类理解世界的完整过程。

### 机器学习（machine learning）

**准确解释：** 机器学习是让计算系统从数据和反馈中调整模型，而不是把每一种情况都写成固定规则的方法。

**【这是一个比方】** 固定规则像给人一本“看见红灯就停”的说明书；机器学习像给系统看许多道路例子，让它自己归纳哪些图像可能是红灯。

**【比方的边界】** 系统归纳的是数据中的数学规律，不会自动理解交通安全的社会意义。训练例子偏差，也会导致判断偏差。

### 生成式人工智能（generative AI）

**准确解释：** 生成式 AI 是能够根据输入生成新文字、图片、声音、视频或代码的系统。它不是只在已有选项中选择，而是组合学到的规律产生新内容。

**【这是一个比方】** 它像一间可以按要求起草新稿件的工作室，而不只是一个从档案柜拿出旧文件的管理员。

**【比方的边界】** 生成内容并不表示系统拥有作者的人生经验或创作意图。新组合也可能复制偏见、混淆事实或接近训练材料中的已有作品。

### 训练（training）

**准确解释：** 训练是用数据和反馈反复调整模型参数，使模型在某类任务上的输出逐渐符合训练目标的计算过程。训练大型模型需要大量计算资源，通常在用户开始聊天之前已经完成。

**【这是一个比方】** 训练像学生做大量练习题并根据批改调整答题习惯。

**【比方的边界】** 模型没有学生的主观体验，也不会因为一次聊天就自动把内容永久学会。训练中的“改正”是数学优化，不等于理解错误的社会后果。

### 推理或运行（inference）

**准确解释：** 在 AI 工程中，推理是训练完成的模型接收一个新输入并计算输出的过程。用户每次提问、生成图片或识别声音，通常都在触发一次或多次推理。

**【这是一个比方】** 训练像厨师长期学艺，推理像厨师今天根据一张订单实际做一道菜。

**【比方的边界】** 模型推理不是人类在意识中权衡证据的同义词。有些产品把“推理模型”作为能力名称，也不表示其思维过程等同于人。

### 参数（parameter）

**准确解释：** 参数是模型在训练中调整出来的大量数字。它们共同影响模型怎样把输入转换为输出。产品说“几十亿参数”是在描述模型规模的一种方式。

**【这是一个比方】** 可以把参数想成调音台上的大量旋钮：每个旋钮单独看意义有限，许多旋钮共同决定最后声音。

**【比方的边界】** 参数不是可以逐个读懂的知识卡片，也不能简单说某个参数专门保存某一事实。参数更多通常意味着容量更大，但不自动意味着每项任务更好。

### 数据集（dataset）

**准确解释：** 数据集是为了训练、微调或评估而组织起来的一批数据，可以包括文字、图片、声音、标签和正确答案。

**【这是一个比方】** 数据集像一套教材、练习题和参考答案的集合。

**【比方的边界】** 数据集可能规模极大、来源复杂，也不一定经过像正式教材那样的编辑审查。错误、重复、偏见和未经授权内容都可能混入其中。

### 数据污染（data contamination / data pollution）

**准确解释：** 本书用数据污染概括训练、微调或检索资料中混入错误、重复、过期、来源不明、比例失衡或不适合当前任务的内容。污染可能无意发生，也可能来自低质量收集；它不自动表示存在攻击者。

**【这是一个比方】** 它像资料仓库里混入旧版本、重复复印件和没有署名的便条，整理者若不核对，就可能把错误材料一起归档。

**【比方的边界】** 模型数据不是真实纸张，错误也不会自动露出颜色。过滤、去重和人工审核能降低风险，但不能保证每条事实永久正确。

### 数据投毒（data poisoning）

**准确解释：** 数据投毒是攻击者故意把设计过的数据放进训练、微调或其他学习来源，以降低模型质量、操纵特定答案或植入触发行为。它是数据污染中的恶意安全问题，强调意图和攻击设计。

**【这是一个比方】** 它像有人故意把一批改过数字的假记录混入档案，希望以后查询者得到指定的错误结论。

**【比方的边界】** 真实投毒可能只改动少量复杂样本，也不一定能从单次回答直接证明。普通错误、观点分歧和资料过时不能自动定性为投毒。

### 模型坍塌（model collapse）

**准确解释：** 模型坍塌指生成模型在递归使用前代模型输出作为训练数据的某些条件下逐渐退化，丢失原始数据中较少见的模式或多样性。它是一类研究现象，不表示所有使用合成数据的训练都会失败。

**【这是一个比方】** 它像不断复印上一张复印件而不保留原稿，浅色细节可能一轮轮消失。

**【比方的边界】** 模型训练不是复印。高质量原始数据、经过验证的合成数据、合理比例和评估方法都可能改变结果，不能把这个比方写成必然结局。

## 二、语言模型怎样处理文字

### Token（文字片段）

**准确解释：** Token 是模型处理文字时使用的基本片段，可能是一个汉字、一个词的一部分、标点或几个字符。API 的文字使用量经常按输入和输出 Token 计费。

**【这是一个比方】** Token 有点像拼图块：一段话先被拆成许多块，模型再根据已有块预测下一块。

**【比方的边界】** Token 不总等于一个完整汉字或单词，不同模型的拆分方式也可能不同。模型不是先像人一样理解整句话，再机械拼图。

### 大型语言模型（Large Language Model, LLM）

**准确解释：** LLM 是在大规模文字和其他数据上训练、能够执行广泛语言任务的模型。它可以对话、摘要、翻译、写作、解释代码，并在接入工具后完成搜索或计算。

**【这是一个比方】** LLM 像一位读过很多类型材料、能够迅速起草多种文字的通才助手。

**【比方的边界】** 它不是受过真实职业训练、能承担责任的通才。读过的资料可能有错，生成的引用也可能不存在；“语言能力强”不等于“事实永远可靠”。

### 小型语言模型（Small Language Model, SLM）

**准确解释：** SLM 通常参数更少、运行资源更低，有时可以直接在手机或电脑上运行。它可能适合快速、重复、范围明确的任务。

**【这是一个比方】** 大型模型像设备齐全的综合工作室，小型模型像随身工具箱：工具较少，但携带方便，特定小任务可能更快。

**【比方的边界】** 大小没有全球统一分界，工具箱也不一定比工作室更保护隐私；必须确认任务是否真的在本机完成、是否仍会联网。

### 上下文（context）

**准确解释：** 上下文是模型在当前一次任务中能够参考的提示词、对话历史、文件片段和工具结果。它与训练时已经形成的参数知识不同。

**【这是一个比方】** 上下文像摆在助手当前书桌上的材料；模型参数则更像助手此前训练形成的工作习惯。

**【比方的边界】** 模型没有真正的书桌。上下文以 Token 形式进入计算，而且材料放进去不代表每个细节都会被同等重视。

### 上下文窗口（context window）

**准确解释：** 上下文窗口是一次请求中模型能够处理的 Token 总量范围，通常包括输入、对话记录、检索资料和输出。窗口越长，理论上能容纳的材料越多。

**【这是一个比方】** 它像一次会议桌能摊开的文件数量。桌子大，可以放更多材料。

**【比方的边界】** 桌上放得下不等于与会者读懂了每一页。长上下文模型也会遗漏中间细节、混淆版本或错误建立关系。

### 知识截止时间（knowledge cutoff）

**准确解释：** 知识截止时间通常指模型训练知识大致覆盖到的时间边界。超过该时间的新事件，除非产品联网搜索或提供新资料，否则模型可能不知道。

**【这是一个比方】** 它像一本在某日交稿的百科全书，交稿之后发生的事不会自动出现在已印出的内容里。

**【比方的边界】** 模型不是按日期整齐出版的百科；截止日前的罕见事实也可能不知道，截止日后的少量信息也可能通过后续训练、工具或产品更新进入。

### 幻觉（hallucination）

**准确解释：** 在生成式 AI 中，幻觉通常指模型生成了听起来合理、实际却错误、无依据或与来源不符的内容，例如编造书名、日期、引文或人物经历。

**【这是一个比方】** 它像一个人在记不清时，仍用符合故事结构的细节把空白补满。

**【比方的边界】** 模型并没有人类的视觉幻觉或故意撒谎体验。“幻觉”是行业比喻，真实机制是生成目标没有自动保证事实正确。

## 三、图片、声音和多种信息形式

### 多模态模型（multimodal model）

**准确解释：** 多模态模型可以处理文字、图片、声音或视频中的两种以上形式，有些还可以在不同形式之间转换。

**【这是一个比方】** 它像一位既能读信、看照片、听录音，又能把几种材料放在一起讨论的助手。

**【比方的边界】** 产品可能不是一个模型完成全部工作，而是多个模型接力。“支持图片”也不表示能准确理解所有医学影像、图表或手写字。

### 光学字符识别（Optical Character Recognition, OCR）

**准确解释：** OCR 把图片中的印刷字或手写字识别成可以搜索、复制和编辑的文字。

**【这是一个比方】** OCR 像抄写员看着照片，把看到的字重新打出来。

**【比方的边界】** 它不会自动理解全部语义，模糊字、竖排、特殊字体和手写体都可能抄错。得到可编辑文字后仍需对照原图。

### 语音识别（speech recognition）

**准确解释：** 语音识别把录音或实时讲话转换成文字。口音、噪声、多人重叠和专业词都会影响准确性。

**【这是一个比方】** 它像会议记录员一边听一边打字。

**【比方的边界】** 系统没有记录员对人物关系和现场背景的完整理解。文字排得整齐，也可能把姓名、药名和数字听错。

### 语音合成（Text-to-Speech, TTS）

**准确解释：** TTS 把文字转换成语音，可用于朗读、导航和语言学习。有些服务可以控制音色、语速和情绪，甚至模仿真人声音。

**【这是一个比方】** 它像一位按照文字稿朗读的播音员。

**【比方的边界】** 合成声音不是有情感经历的真人。模仿某个人的音色还可能造成冒充、诈骗和授权问题。

### 图片生成（image generation）

**准确解释：** 图片生成模型根据文字或参考图生成新画面。它学习了视觉和文字之间的关系，但不会先建立一个完全真实的世界再拍照。

**【这是一个比方】** 它像一位见过许多视觉作品、根据委托快速提出画面草案的插画师。

**【比方的边界】** 模型不是拥有创作意图和职业责任的真人插画师，也可能生成错误手指、乱码、相似作品或不真实历史细节。

### 局部重绘（inpainting）

**准确解释：** 局部重绘是选定图片的一块区域，让模型根据周围内容和提示词重新填充。它常用于去除物体、补背景或修复损伤。

**【这是一个比方】** 它像只请修复师处理画面上的一小块，而不重画整幅作品。

**【比方的边界】** 模型填入的是推测内容，不一定恢复了原来真实存在的细节。框选区域外有时也会发生变化，必须对照原图。

### 放大与增强（upscaling / enhancement）

**准确解释：** 放大与增强提高图片像素数量、对比度或可见细节。AI 增强可能根据训练规律补出看起来合理的纹理。

**【这是一个比方】** 它像把一张小照片放大后，再请人把模糊边缘描得更清楚。

**【比方的边界】** 描出来的清楚不一定是历史原貌。AI 无法从已经丢失的信息中凭空恢复唯一正确答案。

## 四、产品怎样连接模型和资料

### 应用程序（application, App）

**准确解释：** App 是用户直接操作的软件产品，包括界面、账号、付款、权限、数据保存和后台服务。App 可以拥有自己的模型，也可以调用其他公司的模型。

**【这是一个比方】** App 像一家餐厅：用户看到菜单、座位和服务，后厨食材却可能来自许多供应商。

**【比方的边界】** 软件的数据流比餐厅复杂得多，同一个按钮可以同时联系多个服务器。界面漂亮也不能证明模型来源、安全或价格合理。

### 用户界面（User Interface, UI）

**准确解释：** UI 是用户看见和操作的部分，例如按钮、菜单、输入框和结果页面。

**【这是一个比方】** UI 像汽车的方向盘、仪表盘和踏板，是驾驶者接触车辆的部分。

**【比方的边界】** UI 不等于后台能力。相同模型可以有完全不同界面，相似界面也可能连接完全不同的服务。

### 图形用户界面（Graphical User Interface, GUI）

**准确解释：** GUI 是以窗口、图标、按钮、菜单和触摸操作为主的用户界面。手机 App 和网页聊天通常属于图形用户界面。GUI 可以让操作更直观，但它只是产品的一层。

**【这是一个比方】** GUI 像家用电器上的屏幕和按钮，让用户不用看内部线路也能操作。

**【比方的边界】** 软件界面不是真实电器面板；后台可以随时连接不同模型、规则和服务器。按钮数量不能证明模型数量。

### 终端（terminal）与命令行界面（Command-Line Interface, CLI）

**准确解释：** 终端是用户用文字命令与计算机程序交互的环境；CLI 是程序接受这些文字命令的操作方式。LLM 可以通过终端工具连接云端模型，也可以在终端启动本地模型，不一定需要单独制作网页或 App。

**【这是一个比方】** GUI 像看菜单点菜，CLI 像把要求按文字直接交给工作台。两种方式可以把任务交给同一个后厨。

**【比方的边界】** 终端不是后厨，CLI 也不是模型。终端命令可能拥有读写文件或安装软件的权限；是否联网、怎样计费、数据去哪里，要看实际工具和模型配置。

### 应用程序接口（Application Programming Interface, API）

**准确解释：** API 是两套软件按照规定格式互相请求和返回结果的接口。第三方 App 常通过 API 调用模型公司的服务。

**【这是一个比方】** API 像餐厅前台的点菜单：顾客按菜单格式下单，前台把请求交给后厨，再把结果送回。

**【比方的边界】** API 不是真人前台，不理解全部意图，只接受规定的数据、权限和格式。API 还可能计费、限速和记录请求。

### API 密钥（API key）

**准确解释：** API 密钥是一串用于识别调用者、控制权限和计算费用的秘密字符。泄露后，别人可能冒用额度或访问相关服务。

**【这是一个比方】** 它像一张既能开门又会把消费记到您账上的工作证。

**【比方的边界】** API 密钥不是普通登录密码，也不能靠隐藏在网页代码里保证安全。不同密钥拥有的权限可能不同，泄露后应在官方平台撤销。

### 服务器（server）

**准确解释：** 服务器是向其他设备提供数据或计算服务的计算机系统。手机 App 常把问题发送到远程服务器，由服务器运行模型再返回结果。

**【这是一个比方】** 服务器像集中处理业务的后台办公室，许多前台窗口都把任务送到这里。

**【比方的边界】** 服务器不一定是一台实体机器，也可能是分布在多个数据中心的服务。数据经过哪里要以产品架构和条款为准。

### 云端（cloud）与本地运行（on-device / local）

**准确解释：** 云端处理通常指任务在服务商管理的远程计算系统完成；本地运行指主要计算在用户自己的手机或电脑上完成。

**【这是一个比方】** 云端像把衣服送到洗衣店，本地运行像在家里的洗衣机处理。

**【比方的边界】** “本地功能”仍可能上传统计、备份或部分数据；“云端”也不是数据飘在天空。必须查看具体网络行为和隐私说明。

### 模型路由（model routing）

**准确解释：** 模型路由是产品根据任务、价格、速度或会员等级，把不同请求交给不同模型的机制。

**【这是一个比方】** 它像医院分诊台：简单问题去普通窗口，复杂问题转给专门科室。

**【比方的边界】** 路由器不一定正确理解任务，也可能主要按成本而非质量选择模型。产品若不披露，用户可能不知道实际使用了哪个版本。

## 五、怎样让模型参考特定资料或改变行为

### 提示词（prompt）

**准确解释：** 提示词是用户或程序交给模型的任务、问题、材料和限制。提示词可以是文字，也可以包含图片、声音或文件。

**【这是一个比方】** 它像交给合作者的一份工作说明。

**【比方的边界】** 模型不是会主动澄清一切的合作者。提示词再清楚，也不能给模型增加没有的资料、工具、权限或专业资格。

### 系统提示词（system prompt）

**准确解释：** 系统提示词是产品在后台预先设置的高层工作说明，通常规定角色、格式、安全边界和工具使用。普通用户往往看不到完整内容。

**【这是一个比方】** 它像单位给员工的内部工作手册，客户只看到最终服务。

**【比方的边界】** 系统提示词不保证模型每次完全遵守，也可能被其他指令、工具结果或程序规则共同影响。

### 提示词工程（prompt engineering）

**准确解释：** 提示词工程是设计、测试和改进模型输入，使任务、材料、输出和限制更明确的方法。

**【这是一个比方】** 它像反复改进一份工作委托书：先发现对方误解了哪里，再补上缺失条件。

**【比方的边界】** 它不是控制模型的咒语，也不能修复错误资料或突破模型能力上限。重要任务仍需测试、证据和人工验收。

### 知识库（knowledge base）

**准确解释：** 知识库是为检索和回答组织的一组资料，可以是文件、网页、数据库记录或产品说明。它的范围由建设者决定。

**【这是一个比方】** 它像一个经过挑选的资料室。

**【比方的边界】** 被放进资料室的内容不自动真实、完整或中立。商家可以只放有利于自己的材料，也可能忘记更新旧版本。

### 嵌入（embedding）与嵌入模型（embedding model）

**准确解释：** 嵌入模型把文字、图片等内容转换成一组数字，使意义或特征相近的内容在数学空间中更接近。它常用于语义检索、聚类和推荐。

**【这是一个比方】** 它像图书管理员不是按书名逐字相同，而是按主题把相近资料放到附近书架。

**【比方的边界】** 数学距离不是人类意义的完整理解，也会受训练数据影响。相近不等于事实一致，更不等于来源可靠。

### 检索增强生成（Retrieval-Augmented Generation, RAG）

**准确解释：** RAG 先从外部语料或数据源中检索相关片段，再把这些片段和问题交给生成模型回答。来源可以是内部文件、网页、数据库或动态索引，常用于最新资料和需要引用的问答。

**【这是一个比方】** 它像一场“开卷考试”：答题前先从约定的资料范围找相关页，再组织答案。

**【比方的边界】** 模型不是严格按考试纪律答题的学生。它可能找错资料、遗漏反例、误读片段或补入自身知识；资料架本身也可能片面。

### 微调（fine-tuning）

**准确解释：** 微调是在已有模型基础上，用特定示例继续训练，使它更稳定地遵守某种格式、风格或任务行为。全量微调可能更新全部或大部分基础权重；LoRA 等方法可以冻结基础权重，增加并训练较小的适配参数。

**【这是一个比方】** 它像一位已有通识训练的员工，再接受一段岗位专项训练。

**【比方的边界】** 微调不等于获得专业执照，也不适合频繁更新每天变化的事实。专项训练材料有偏见，模型也可能更稳定地重复偏见。

### 记忆（memory）

**准确解释：** AI 产品中的记忆通常指系统保存用户偏好、背景、过去对话摘要或结构化记录，并在以后任务中检索或重新提供给模型；具体实现并不唯一。

**【这是一个比方】** 它像服务人员为熟客保存了一张偏好卡。

**【比方的边界】** 这不是人类有意识的回忆。保存什么、保存多久、能否删除由产品设计决定，也可能带来画像和隐私风险。

### 工具调用（tool use / function calling）

**准确解释：** 工具调用让模型按规定格式使用搜索、计算器、日历、数据库、邮件或程序执行器等外部功能。

**【这是一个比方】** 它像一位助理不会亲自完成所有专业操作，但可以拿起电话联系不同部门。

**【比方的边界】** 模型可能联系错工具、填写错参数或误读返回结果。涉及付款、发送和删除时仍需人工确认。

### 智能体（agent）

**准确解释：** 在当前 AI 产品中，智能体通常指能够围绕目标拆分步骤、调用工具、检查结果并继续行动的系统。这个词在行业中没有完全统一的产品定义。

**【这是一个比方】** 它像得到一个目标后，会自己列计划、找资料、使用工具并汇报进度的项目助理。

**【比方的边界】** 智能体不具有人的责任、常识和授权判断。它能连续行动，恰恰意味着权限错误可能被连续放大，因此需要审批和停止机制。

## 六、怎样比较质量、速度和版本

### 基准测试（benchmark）

**准确解释：** 基准测试是一组固定任务和评分方法，用于比较模型在某些能力上的表现，例如知识问答、数学、代码或图像理解。

**【这是一个比方】** 它像统一考试：同一批题有助于横向比较。

**【比方的边界】** 考试高分不等于实际工作全面可靠。厂商可能针对常见题训练，测试也可能与普通用户的中文、长文档和真实性需求不一致。

### 延迟（latency）

**准确解释：** 延迟是从用户发出请求到系统开始或完成返回结果所需的时间。模型大小、网络、排队和工具调用都会影响延迟。

**【这是一个比方】** 它像点餐后等多久开始上菜。

**【比方的边界】** 快慢不只由“后厨水平”决定，也受网络、服务器负载和回答长度影响。更快不表示更准，更慢也不自动表示思考更深。

### 速率限制（rate limit）与使用额度（quota）

**准确解释：** 速率限制规定一段时间内最多能请求多少次或处理多少 Token；使用额度规定账号可使用的总量或资源量。

**【这是一个比方】** 速率限制像闸机控制每分钟进多少人，额度像一张票一共允许进几次。

**【比方的边界】** 不同产品按次数、Token、图片、计算时间或积分计量，不能只看“无限”两个字。所谓无限通常仍受公平使用规则限制。

### 模型版本（model version）

**准确解释：** 模型版本标识某次训练、更新或部署的模型。App 版本、模型版本、搜索版本和知识库版本是不同东西。

**【这是一个比方】** App 像电视机外壳，后台模型像电视台播出的节目；外壳没换，节目仍可能已经改版。

**【比方的边界】** 软件系统可以在一次请求中路由多个模型，也可能使用不公开的内部版本，因此真实情况比电视比方更复杂。

### 开放权重（open weights）与闭源服务（proprietary service）

**准确解释：** 开放权重通常指模型训练后的参数文件在某种许可证下可下载使用；闭源服务通常只通过 App 或 API 提供能力，不公开核心权重。开放权重不必然等于所有训练数据和代码完全开源。

**【这是一个比方】** 开放权重像允许把一台成品机器带回自己的厂房运行；闭源服务像只能把订单交给对方工厂加工。

**【比方的边界】** 拿到“机器”仍需要设备、技术和安全维护；许可证也可能限制用途。闭源服务也可能提供更好的维护和安全控制。

## 七、AI 辅助编程常见词

### 程序代码（code）

**准确解释：** 代码是用编程语言写出的、可以由计算机执行或解释的指令。代码能够自动重复任务，也可能自动重复错误。

**【这是一个比方】** 代码像给机器的一份非常具体的操作清单。

**【比方的边界】** 自然语言允许含糊，代码通常要求更严格。AI 生成的代码即使语法像真的，也可能调用不存在的功能或产生安全问题。

### 依赖（dependency）

**准确解释：** 依赖是一个程序运行时需要的其他软件包、系统组件或外部服务。依赖的版本和安全状态会影响程序。

**【这是一个比方】** 一个舞台节目依赖灯光、音响和场地；少了其中一项，节目可能无法正常进行。

**【比方的边界】** 软件依赖可能自动下载并执行代码，风险比普通舞台设备更隐蔽。依赖越多，维护和供应链风险通常越复杂。

### 运行环境（runtime environment）

**准确解释：** 运行环境是程序执行所处的操作系统、软件版本、硬件、权限和配置。相同代码在不同环境中可能有不同结果。

**【这是一个比方】** 同一株植物在不同土壤、气候和光照下生长状况不同。

**【比方的边界】** 程序环境可以被精确记录和复制，植物比方只能帮助理解“条件会影响结果”，不能解释具体兼容性。

### 错误信息（error message）

**准确解释：** 错误信息是系统在失败时返回的说明，可能包括错误类型、发生位置和调用过程。完整错误信息常能帮助定位问题。

**【这是一个比方】** 它像汽车仪表盘上的故障码，比“车不能开”提供更多线索。

**【比方的边界】** 错误信息可能不完整，也可能包含用户名、路径、网址或密钥，分享前需要删除敏感部分。

### 测试（test）

**准确解释：** 测试是用预先设计的输入、操作和预期结果，检查程序是否符合要求。修改后还要重新测试原有功能。

**【这是一个比方】** 它像验收一把雨伞，不只看外观，还要打开、收起并在水下检查是否漏雨。

**【比方的边界】** 软件可能有大量组合情况，几次通过不能证明永远无错。高风险系统需要更系统的测试、审查和监控。

## 八、隐私和信息判断

### 个人信息（personal information）

**准确解释：** 个人信息是以电子或其他方式记录、与已识别或可识别自然人有关的信息。姓名、手机号、照片、位置和账号记录都可能属于个人信息。

**【这是一个比方】** 单项信息像拼图块；一块看似普通，多块组合后可能拼出具体是谁、住哪里、有什么习惯。

**【比方的边界】** 个人信息的法律定义和处理要求要以适用法律为准，不是只有能直接写出姓名的信息才有风险。

### 敏感个人信息（sensitive personal information）

**准确解释：** 敏感个人信息一旦泄露或被非法使用，容易导致人格尊严受侵害或人身、财产安全受危害，例如生物识别、医疗健康、金融账户、行踪轨迹及特定身份信息。

**【这是一个比方】** 普通资料像家中日常用品，敏感资料像保险柜里的证件和钥匙，需要更严格的保管与使用理由。

**【比方的边界】** 信息敏感程度取决于内容、组合和使用场景，不是放进“保险柜”就绝对安全。法律还规定了具体处理条件和责任。

### 个性化推荐（personalized recommendation）

**准确解释：** 个性化推荐系统根据用户行为、标签和相似人群，选择更可能引起停留、点击或互动的内容。

**【这是一个比方】** 它像一位不断观察您拿过什么书的店员，随后把相似书放到最显眼的位置。

**【比方的边界】** 推荐系统可以同时使用大量用户和实时反馈，不一定真正理解您为什么点击。点击可能源于惊讶或反感，却仍被误认为喜欢。

### 事实、推断与意见（fact, inference, opinion）

**准确解释：** 事实是可以依据证据核验的主张；推断是根据事实和理由得出的结论；意见是个人评价、偏好或价值判断。AI 回答常把三者写在同一段里。

**【这是一个比方】** 看见地面湿是观察事实；判断刚下过雨是推断；觉得雨天很舒服是意见。

**【比方的边界】** “地面湿”也需要确认观察是否可靠，推断还可能有其他解释，例如有人洒水。现实信息比这个例子更复杂，因此要寻找来源和反例。

### 固定快照（snapshot）与移动别名（alias）

**准确解释：** 固定快照是指向一个特定模型版本的标识；移动别名可以在后台改为指向更新版本。两者都会受产品工具、服务器和政策变化影响。

**【这是一个比方】** 固定快照像某年某版纸质字典，移动别名像持续更新的在线词典书签。

**【比方的边界】** 模型不是字典。即使模型固定，系统提示词、搜索、路由和安全规则仍可能改变输出。

### 订阅（subscription）与自动续费（automatic renewal）

**准确解释：** 订阅是在一个周期内持续取得服务权益；自动续费是在当前周期结束时按约定再次扣款。月付、年付、用量包和一次性购买是不同商品。

**【这是一个比方】** 订阅像按月收到杂志，自动续费像到期后系统默认继续寄送并扣下一期费用。

**【比方的边界】** 数字服务的额度、退款和取消渠道由具体协议决定，不能只凭“像订杂志”推断权利。

### 来源追溯（source tracing）

**准确解释：** 来源追溯是沿着转载、引文、图片或数据回到最早可验证的原始材料，并检查其日期和上下文。

**【这是一个比方】** 它像从一张复印件一路找到盖章原件。

**【比方的边界】** 网络内容可被剪辑和反复上传，最早找到的网页也可能不是事实发生时的原始证据。

### 横向阅读（lateral reading）

**准确解释：** 横向阅读是暂时离开当前网页，打开其他来源调查发布者、证据和外部评价，而不是只在原网站内部判断可信度。

**【这是一个比方】** 它像买东西时走出一家店，到别处查品牌、价格和投诉，而不是只读店内海报。

**【比方的边界】** 其他网页也可能互相转载或出错；横向阅读仍需判断来源是否真正独立。

### 回声室（echo chamber）

**准确解释：** 回声室描述一个群体中相似看法不断被重复和强化、不同信息较少进入或较难被接受的传播环境。

**【这是一个比方】** 它像在会回音的房间里听到同一句话多次。

**【比方的边界】** 现实网络并非完全封闭，重复内容也可能来自多个来源；需要追踪传播链，不能只凭相似结论判断。

### 数据最小化（data minimization）

**准确解释：** 数据最小化是只收集或提供完成明确任务真正必要的最少数据，并减少范围、精度和保存时间。

**【这是一个比方】** 请人修改一封信时，只交这封信的必要副本，不交整个家庭档案柜。

**【比方的边界】** 数字副本可被记录和关联；即使资料很少，也要看处理者、用途和删除规则。

### 多因素认证（Multi-Factor Authentication, MFA）

**准确解释：** MFA 在密码之外再要求另一类身份凭据，例如认证器、硬件密钥、短信代码或生物识别，以降低只丢失密码就被接管账号的风险。

**【这是一个比方】** 它像进门既要钥匙，还要出示本人持有的第二种证明。

**【比方的边界】** MFA 不是绝对安全；诈骗者仍可能诱骗用户主动交出验证码，短信方式也有自身风险。

### 个人 AI 工作台（personal AI workbench）

**准确解释：** 个人 AI 工作台是用户自己管理的一组工具、资料分区、提示词模板、核验步骤、付费规则和停止条件，不必是一个单独 App。

**【这是一个比方】** 它像一张整理好的书桌：常用工具有固定位置，重要原件单独保管。

**【比方的边界】** 软件会联网和更新；文件摆放整齐不能自动保证隐私、事实正确或账号安全。
