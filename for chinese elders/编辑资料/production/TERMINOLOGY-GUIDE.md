# 《看懂 AI》术语解释规范

## 目的

本书保留必要的工程词汇，但不能只把英文翻译成中文，也不能只用比方代替原理。技术词第一次进入正文时，原则上按以下顺序解释：

1. **中文名称 + 英文名称或缩写；**
2. **准确解释：** 它是什么、在系统里做什么；
3. **出现位置：** 普通用户会在哪里遇到它；
4. **【这是一个比方】：** 用熟悉的生活关系帮助建立直觉；
5. **【比方的边界】：** 明确技术和生活事物并不完全相同；
6. **【作为用户，这对您意味着什么】：** 说明它怎样影响选择、费用、隐私、答案质量或实际操作；
7. **一个具体例子或反例。**

## 标准写法

> **应用程序接口（Application Programming Interface, API）** 是两套软件按照约定格式互相提出请求、返回结果的接口。第三方 App 可以通过 API 把用户问题发送给模型公司的服务器。
>
> **【这是一个比方】** API 有点像餐厅前台的点菜单：顾客按照菜单能接受的格式下单，后厨处理后再把菜送回来。
>
> **【比方的边界】** API 不是一个真人前台，也不理解顾客的全部意图；它只接受预先规定的数据格式和权限。格式或权限不对，请求就会失败。
>
> **【作为用户，这对您意味着什么】** 一个 App 有聊天功能，不证明开发者训练了自己的模型。它可能只是按使用量付费调用外部 API。购买前应当问清底层模型、版本、数据去向和额外服务价值。

## 使用规则

- 第一次出现英文缩写时必须写出英文全称与中文名称。
- 英文不能单独承担解释；保留英文时，旁边必须有完整中文名称或中文说明。
- 全书不使用日文词语或日文假名。
- 后文可以只用中文简称或缩写，但含义发生变化时重新说明。
- 一个段落最多首次引入两个核心技术词，避免词汇拥挤。
- 比方必须明确写出“这是一个比方”，不能让读者误以为是真实结构。
- 涉及“大脑、学习、记忆、思考、理解”等拟人词时尤其要写比方边界。
- 比方不能承担事实证据；比方后必须回到真实工程过程。
- 不能用“就像人脑一样”结束解释，因为这会掩盖模型与人的差异。
- 产品营销词如“满血版”“专家模型”“智能体”必须区分行业定义与商家自称。
