# 《看懂 AI》手机大字版制作规范

**状态：** 初稿  
**目标：** 降低视觉与操作负担，同时保持成人内容的完整性

## 1. 设计立场

- 大字是可访问性设计，不是智力分级。
- 不使用婴幼儿卡通、夸张警报和居高临下的口吻。
- 插图采用清晰的信息图、真实界面局部和成熟的编辑插画。
- 每一页只承担一个主要认知任务。
- 不用颜色作为唯一的信息区别方式。

## 2. 手机网页基准

以 375—430 CSS 像素宽的竖屏为主要视口。

| 元素 | 建议值 |
|---|---:|
| 正文字号 | 20px；允许切换至 22px、24px |
| 正文行高 | 1.75 |
| 一级标题 | 32px / 1.25 |
| 二级标题 | 27px / 1.35 |
| 三级标题 | 23px / 1.45 |
| 注释最小字号 | 17px；不再缩小 |
| 正文每行 | 约 20—26 个汉字 |
| 段落长度 | 优先 2—5 行，必要时不牺牲因果解释 |
| 点击区域 | 最小 48×48px |
| 正文左右边距 | 20—24px |

建议字体栈：

```css
font-family: "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
```

## 3. 颜色和对比度

- 正文：接近黑色的 `#17202A`，背景 `#FFFDF8` 或白色。
- 正文及重要图形至少满足 WCAG AA 对比度。
- 链接除颜色外必须带下划线。
- 警告不大面积使用红色；红色只标出具体风险动作。
- 用“事实”“推断”“广告”“待核验”四种文字标签配合颜色。

## 4. 每章的固定组件

1. **开篇场景：** 100—180 字。
2. **本章问题：** 一个完整疑问句。
3. **核心图：** 只解释一个关系；可点击放大。
4. **正文卡片：** 一个卡片不超过一个概念。
5. **手机实验：** 3—6 步，每步只有一个动作。
6. **判断卡：** 一屏内可完整截屏。
7. **本章小结：** 3—5 条。
8. **复述题：** 请读者用自己的话解释一次。

## 5. 图片与图解原则

### 应该使用

- “用户—App—API—模型—搜索/知识库—回答”的分层图；
- 官方 App 与相似名称 App 的开发者字段对比；
- 训练、部署和实时搜索的时间线；
- 信息核验的来源树；
- 订阅付款和数据流向图；
- 截图时突出一个字段，其余信息适当弱化。

### 不应该使用

- 把 AI 画成无所不知的人形机器人；
- 用“老人被坏人欺骗”的羞辱性场景；
- 一张图塞入十几个箭头和缩写；
- 只有装饰作用、不能帮助理解的素材图；
- 未经授权的产品截图或人物照片。

## 6. 动态内容设计

模型版本、价格、免费额度、登录方式和地区可用性不固定：

- 正文只解释选择方法；
- 动态表显示“最后核验日期”；
- 印刷版用二维码链接动态表；
- 价格不用“只需”等营销语言；
- 每条产品事实至少保留一个官方来源；
- 超过 90 天未核验的条目显示“可能已变化”。

## 7. 互动与可访问性

- 提供字体大小切换，不依赖双指缩放。
- 所有图片有中文替代文字。
- 图表内容必须同时有文字说明。
- 音频朗读允许 0.75×、1×、1.25× 速度。
- 操作步骤支持“我已完成”逐项勾选。
- 外链打开前显示来源机构与页面用途。
- 不使用自动播放视频、闪烁动画或倒计时催促。

## 8. 可用性测试

每轮至少观察目标读者独立完成：

1. 找到一个 App 的开发者名称；
2. 说出 App 与模型的区别；
3. 找到自动续费说明；
4. 核验一条回答的原始来源；
5. 用两个模型完成一次交叉检查；
6. 建立一个语言学习提示词。

测试者只观察，不代替点击。记录找不到的位置、误解的术语和字体/对比度问题，再修改页面。
